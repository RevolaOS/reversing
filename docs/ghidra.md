# Ghidra

The Ghidra project is rebuilt from the user's own decrypted inputs and the committed analysis. Apple firmware bytes are never committed.

## Requirements

| | |
|---|---|
| Ghidra 12.1.4 | |
| JDK 21 | |
| `revola` CLI | from the installer repository, for `firmware extract-efi`; on `PATH` or given with `--cli` |
| Decrypted 2.0.5 inputs | `osos.bin` and `apple-loader.bin`, checked against `ghidra/profiles/firmware-2.0.5.json` |

## Commands

```sh
python tools/ghidra.py import --inputs <decrypted 2.0.5 inputs>   # builds build/ghidra
python tools/symbols.py push symbols/osos-2.0.5 --ghidra build/ghidra
python tools/symbols.py refresh symbols/osos-2.0.5 --ghidra build/ghidra
python tools/ghidra.py export                                      # writes ghidra/analysis
```

| Command | Does |
|---|---|
| `import` | builds ELF images of OSOS and every NOR module, checks them against `ghidra/programs.json`, runs auto-analysis, applies the saved analysis and verifies the result. Fails if any saved function, symbol, comment or bookmark does not apply |
| `push` | makes the project match the symbols file: functions get their name and prototype, data gets a label, sites get a Note bookmark in category `site`. When auto-analysis has merged a function into the caller that tail-jumps to it, `push` splits it out at the symbols-file address |
| `refresh` | the other way, for entries that already exist: updates `at`, `thumb` and `c` from the project and moves sites with their function |
| `export` | writes what auto-analysis cannot reproduce to `ghidra/analysis` |

Run `refresh` before `push` so edits made in Ghidra are kept. Close the project in Ghidra before running either.

## Exported analysis

Per program, `ghidra/analysis/2.0.5/<program>/` holds:

| File | Records | Use |
|---|---|---|
| `program.json` | SARIF header | language, image base, Ghidra version |
| `memory_map.jsonl` | every block | layout and permissions of the prepared image |
| `entry_points.jsonl` | every entry | analysis seeds |
| `functions.jsonl` | named, typed, thunk or custom-storage functions | names, prototypes and bodies; input to `verify` |
| `symbols.jsonl` | user-defined and imported labels | data and code labels |
| `comments.jsonl` | every comment | analyst notes |
| `datatype.jsonl` | every data type | structures, unions, enums |
| `bookmarks.jsonl` | Note and Info bookmarks | core sites and analyst notes |

Register values, references, code ranges, defined data and analysis bookmarks are regenerated by auto-analysis and not kept. A file larger than 4 MiB is split into `<name>.NN.jsonl`.
